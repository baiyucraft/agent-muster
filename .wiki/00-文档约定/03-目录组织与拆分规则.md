# 目录组织与拆分规则

## 分类与唯一归属

| 目录 | 职责 |
| --- | --- |
| 文档约定 | 页面模板、文档归属、索引和拆分规则 |
| 快速上手 | 项目导读，以及实现后可验证的安装、初始化和最短运行路径 |
| 开发指南 | 跨模块开发约定、验证与测试、Git 协作和复用原则 |
| 模块指南 | 随实现沉淀 Go 中心、中心 dsh 与插件、设备 daemon、Web 和 IM 的职责、运行链路及内部接口 |
| 对外方法 | 面向外部项目或集成方、已经确定对外提供的契约索引 |

按调用方向和受众确定接口文档的归属。Go 中心与插件、daemon 或 Web 的内部协议随对应模块维护。首版设计中的接口与运维细节通过设计稿导航，实际路径、字段与运行步骤随实现补充。[边界与 SSOT 规则](./00-边界与SSOT规则.md)

同一事实只维护一个权威正文。混合页面按职责迁移章节，其他位置用摘要和链接。开发约定放开发指南，实现说明放模块指南。索引主要用于导航。

## 浅目录

从 `.wiki/` 下开始计目录层级。常规为“分类/领域/页面”，需要细分时可使用“分类/领域/主题/子主题/页面”，目录最多四级。各分类随实际内容建立，短文档按主题保留在同级。

每个含 Markdown 页面或其后代的目录维护 `INDEX.md`，包括总索引和中间目录。纯图片等附件目录可由其正文链接。新增、移动和拆分时同步所在目录、上级和总索引，以及 README、项目规则和源码说明中的入链。总索引从 `.wiki/INDEX.md` 开始应能到达每个 Wiki 页面。[项目 Wiki](../INDEX.md)

## 正文规模与整理

正文行数排除文件开头合法的 YAML 前置元数据，计入标题、空行、表格、示例与代码块。LF 和 CRLF 采用相同计数，文件末尾单个换行作为结束符。

| 正文行数 | 处理 |
| --- | --- |
| 少于 800 行 | 常规维护 |
| 800 至 999 行 | 提示优化，评估重复内容和主题是否适合拆分 |
| 达到 1000 行 | 检查报错，按主题整理或拆分后再交付 |

在已授权的文档维护范围内，按完整主题拆为同名目录中的 `INDEX.md` 和若干职责清晰的页面，保持表格、示例和代码块完整。达到第四级后采用同级页面组织主题。迁移正文时同步所有入链，并将原位置的内容汇入唯一正文。

## 交付检查

- 用页面模板核对 YAML 前置元数据，检查本地相对链接和标题锚点。
- 从 `.wiki/INDEX.md` 检查页面可达、各级目录索引、四级目录深度和正文行数。
- 核对引用的设计状态、源码、配置和测试证据，确保表述与来源一致。
