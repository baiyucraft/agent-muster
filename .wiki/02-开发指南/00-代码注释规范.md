# 代码注释规范

[返回开发指南](INDEX.md)

## 通用原则

- 默认使用中文。类名、函数名、业务字段、协议和第三方库名称保留原文。
- 说明职责、业务语义、前置条件、约束、单位、默认值、副作用、异常和恢复边界。说明的详细程度取决于实际契约和复杂度。
- 稳定的架构与维护指南写入 Wiki，源码注释保留对应位置需要理解的契约和原因。命名或职责不清时先改进设计。
- 修改实现时同步更新或删除过期注释。确需保留待办时标记并关联可追踪事项。
- 不写入密钥、令牌、密码、真实个人数据、服务器凭据或仅适用于本机的路径。

## Go 与 TypeScript

- Go 的包、导出类型和导出函数通过 doc comment 说明契约，导出声明的说明以符号名开头。并发使用、阻塞时机、上下文取消、错误返回与资源释放由相应的公开入口说明。
- TypeScript 声明是类型的唯一事实来源。JSDoc 用于说明参数范围、空值含义、默认行为、返回结果、异步完成条件及失败语义。字段契约写在类型定义处，调用说明引用已有定义。
- 内部方法、局部变量和回调按语义需要补注释。状态推进、事务与进程交接等代码在实现附近说明原因和维护约束。

## 任务及运行契约

以下是首版设计中应就地说明的边界，具体字段与入口随实现确定。见[首版设计稿](../../.docs/agent-muster-v0.1.md)。

| 位置 | 注释应说明的语义 |
| --- | --- |
| 持久记录和接口字段 | 任务 ID、运行 ID、请示 ID 和原生会话引用分别标识什么。设备事件序号的唯一性范围、中心事件游标的排序范围和重连的起点。 |
| 任务进度与回执 | 接收、执行、结果落盘与中心确认的区别。重复回执如何取回确认，迟到回执如何归到所属轮次。 |
| 执行与停止 | 取消请求由谁转交、什么时候视为进程退出、停止后如何保留执行记录和原生会话。 |
| 重试与重启 | 能直接重试的待投递动作、须先核对外部证据的动作，以及恢复后如何判断下一轮可以接手。 |
| 用量及日志字段 | 数据来源、单位、取样范围与缺失值。未知用量应以独立语义表达。 |

## 检查与修复

- ESLint 从 Web API、共享状态入口、Wails 桥接类型和 dsh 插件开始，检查公开声明的 JSDoc 正文及可核对的参数、返回信息。测试与工具配置执行基础代码检查。
- 对照 Git 候选执行 Go 注释检查，覆盖变化的导出函数、方法、类型和包注释。运行入口及候选参数见 [验证与测试](01-验证与测试.md#工程检查入口)。
- Review 用真实实现核对业务注释，重点检查权限、状态、空值、取消和恢复。用 ESLint 或 gofmt 修复可判定的格式问题，依据代码契约补写说明并复查差异。
