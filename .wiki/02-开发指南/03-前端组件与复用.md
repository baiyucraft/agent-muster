# 前端组件与复用

[返回开发指南](INDEX.md)

## 布局、交互与文案

Web 和设备端都应通过页面结构和操作反馈，让用户直接看懂界面。

- 用清晰的视觉层级、分组、留白和对齐表达内容关系。突出主要动作，把操作放在它影响的对象旁边。通过控件状态和反馈说明操作是否生效、接下来可以做什么。
- 默认省去口号式文案、教学段落、每个区块的常驻帮助说明，以及装饰性徽标、重复标题和复述控件作用的标签。确实有用的次要说明，优先就近放在 info 图标的 tooltip 中，让鼠标悬停和键盘聚焦都能打开，支持触屏时也提供可点开的入口。
- 必要的字段标签、状态反馈、输入限制、错误恢复提示和关键操作后果应在需要时直接可见。图标按钮要有可访问名称。
- 评审时以首次使用者的视角走一遍主要流程。去掉辅助说明后，用户仍应能判断下一步点哪里、点击会发生什么。需要靠长段文字才能完成常用操作时，先调整布局、控件或操作反馈。

## 质感、动效与截图验收

- 视觉质感和流畅动效是核心要求。用一致的字号、间距、对齐和控件状态建立清晰的阅读节奏。动效用于反馈操作、说明状态变化或维持切换前后的空间关系，保持连贯，避免布局跳动、画面闪烁和操作延迟。尊重系统的减少动态效果设置。
- 有可见界面变化时，在受影响的 Web 页面或桌面应用中截图验收，按改动覆盖关键状态、主题和窗口尺寸。需要打磨时，按「截图、比对、调整、再截图」迭代，直到层级、对齐、间距和文案达到预期。动效的衔接和操作反馈要实际触发验证，截图用于核对静态画面及关键状态。

## 组件归属

- 中心 Web 与 Windows 客户端在构建时导入同一份 [`ui/token.css`](../../ui/token.css)。在此维护浅深色主题、字体、强调色、状态色、间距、控件尺寸和圆角。页面样式负责各自的布局及原生窗口控件。修改共享变量后，检查两端的浅色、深色和窄屏。
- 先查现有组件，再扩展或提取。单一页面的交互留在页面附近。同一模块的重复布局与交互由模块共享。存在实际跨模块复用时，再沉淀到应用共享层。
- 共享组件通过明确的 Props 接收输入，通过回调表达用户意图，通过 `children` 或具名渲染属性承接调用方内容。
- 页面或业务模块负责查询、权限、导航、动作提交和刷新。通用展示组件只依赖调用方提供的数据，视觉场景差异由调用方组合。
- 加载、空态、失败和禁用状态显式表达。操作按钮和状态展示提供可读的文字，使用颜色辅助区分。
- 新增实际投入使用的共享组件时，登记源码入口、调用场景和契约边界。

## 对话、看板和任务详情

任务状态以服务端数据为准。看板任务卡和任务详情可以共享状态文案与展示组件。主对话展示请示状态时，可以复用同样的映射，从对话条目的请示数据取值。设备连接状态和任务运行状态各自呈现。诸如设备离线时显示最后收到的运行状态，以及已答复后仍等待原生会话处理，均按[首版设计稿](../../.docs/agent-muster-v0.1.md)的状态语义实现。

快照、SSE 连接、重连游标和事件去重由同一数据入口管理。页面从共享数据读取视图，任务卡和详情组件本身通过输入更新。新增需要实时刷新的组件时，沿用该入口更新数据。
