# 推送前

1. 根据用户要求和实际 Git 配置核对 remote、目标 ref 和待推源 SHA。对已确认的目标定向 fetch，核实远端 SHA，记录 merge-base、ahead/behind 和 `<远端SHA>..<源SHA>` 的待推提交。新分支使用已核实的祖先基线。
2. 对每个目标记录最终 tree，逐文件检查从已核定基线到待推 tree 的累计差异，验证跨提交组合及接口调用方。再核对待推历史中存在的敏感文件或误入产物，即使后续提交已删除。工作区和 index 用于识别遗漏与验证污染。
3. 对累计范围运行 `git diff --check <基线> <源SHA>`，执行语义 Review 与证据验证。可复用符合最终候选的已审文件和测试证据，补查跨提交行为。发现已提交的问题时，按授权修复，新增修复提交走提交前流程，再对新 SHA 复验。[共用 Review 流程](git-delivery.md) · [提交](commit.md)
4. 确认已有目标的远端 SHA 是待推 SHA 的祖先。使用 `git push <remote> <已审SHA>:refs/heads/<目标分支>` 显式发送已审提交，再用 `git ls-remote` 回读目标 ref，核对实际 SHA 和本地状态。响应丢失时先回读远端，避免重复执行。

仅要求推送前检查时，刷新已确认的目标并报告。远端前移或拒绝时先刷新状态核对原因。仍可快进且已获授权时，按新目标基线补查受影响内容再重试。遇到分叉、冲突或需要历史改写时说明实际情况与方案。推送授权覆盖确认目标上的普通推送，额外的提交、历史操作和部署遵照相应授权。
