# 代码、验证和文档规范

## 工作范围和实现

- 修改前核对仓库、分支、暂存区和工作区，保留现有更改。需隔离并行修改时，在仓库的 `.worktree/` 下以特性名创建 worktree，交付后确认需保留的修改和提交再清理。
- 从真实入口及调用方确认契约，沿用现有实现和数据结构。从空值、历史记录、并发、部分失败和重试检查状态是否一致。接口、配置、迁移、调用方和必要测试随契约更新。
- 仓库有 `.codegraph/` 时先用 CodeGraph 追入口与消费者，再以实际源码、配置和测试核对动态注册及运行行为。

## 跨组件契约与配置

| 改动 | 核对范围 |
| --- | --- |
| Hub HTTP 或 SSE | Go handler、`api/openapi.yaml` 和实际 Web／daemon／dsh 消费方。检查权限、字段与缺省值、错误映射、事件顺序及重连恢复。 |
| 本机 Agent 或桌面入口 | 核对 runner、工作目录、进程退出、原生会话与本机记录。Wails 绑定变化使用仓库任务重新生成，核对绑定和设备界面调用方。 |
| 持久化和交接 | 核对 PostgreSQL 与设备 SQLite 的适用存储边界、历史迁移、事务、幂等及恢复。声明任务、运行、会话、投递及版本字段的来源、身份和写入时机。 |
| 运行配置 | 从装配入口查实际默认值、来源优先级、空值语义与生效时机。同步受影响的示例、部署模板和消费方。凭据从现有运行配置入口读取，示例及验证记录脱敏。 |

Go 和 Wails 的本地运行、依赖和构建入口以当前配置及设备 Taskfile 为准。[快速上手](../../../../.wiki/01-快速上手/INDEX.md)

## 代码注释

- 默认用中文，保留代码标识符、字段、协议和第三方名称。说明职责、约束、输入范围、单位、默认值、副作用、失败行为和恢复条件，详略取决于契约。同步更新过期注释。仍需保留的待办应关联可追踪事项。源码和文档中屏蔽凭据、令牌、敏感数据及仅适用于本机的路径。
- Go 包使用 `Package <包名>` 开头的包注释。导出类型和函数使用以符号名开头、紧贴声明的 doc comment。需要说明并发使用、阻塞时机、上下文取消、错误返回和资源释放时，写在对应入口。
- TypeScript 由声明定义类型，JSDoc 解释参数范围、空值、默认值、返回值、异步完成条件及失败语义。字段契约写在类型定义处，调用点引用该定义。
- 新增或修改的业务入口、共享函数及领域类型应有可读正文。需要标签时用 `@param` 说明匹配签名的参数，`@returns` 说明实际结果、空值或完成条件，`@throws` 说明调用方可处理的错误。对 `Promise<void>` 写明何时完成和失败如何传递。类型字段说明身份来源、单位、缺省值或所有权，按业务需要选取。简单局部回调和生成代码按其入口维护说明。
- 状态推进、事务和进程交接附近说明维护不变量。区分任务 ID、运行 ID、请示 ID、原生会话引用。声明设备事件序号的唯一范围以及中心事件游标的排序和重连规则。
- 区分运行接收、执行、结果落盘与 Hub 确认，说明重复和迟到回执的处理方式。说明取消归属、进程退出条件、会话保留、可重试动作以及重启后的核对依据。用量和日志注明来源、单位、取样范围及缺失值。
- 变更注释时保留编译、生成和 lint 指令。自动工具的结构规则通过后，仍需逐条核对注释是否与实现一致。长期架构和维护说明归 Wiki。[项目代码注释规范](../../../../.wiki/02-开发指南/00-代码注释规范.md)

## 代码风格与依赖

- Go 使用 gofmt。TypeScript 沿用所属模块的严格类型配置，通过类型收窄表达未知输入，类型专用依赖使用 `import type`。JS／TS 沿用当前源码中的两空格缩进、单引号及省略分号风格，调整导入时核对模块初始化顺序。
- 依赖变更同时审查对应 manifest 和锁文件、引用入口和构建行为。生成文件从源定义重新生成，复核生成差异。
- ESLint 的实际规则和排除范围见根 `eslint.config.mjs`。使用 `pnpm run lint` 只读检查，或对明确文件执行 `pnpm exec eslint --fix <文件...>`。按实际实现补写业务注释并审查修复差异。

## 界面、React 组件和实时数据

- 实现和 Review 界面时，沿主要操作核对入口、下一步和反馈。需要辅助说明才能找到常用操作时，先调整布局与交互，并按规范核对文案保留范围。[布局、交互与文案](../../../../.wiki/02-开发指南/03-前端组件与复用.md#布局交互与文案)
- 先查现有组件、Hooks、API client 和样式。优先复用或扩展匹配的入口。已有多处稳定用法时评估提取。单页行为留在页面，模块内复用留在模块，有实际跨模块调用时再放应用共享层。
- 页面或业务模块负责查询、权限、导航、动作提交和刷新。展示组件通过 Props 接收数据，通过回调表达操作，通过 `children` 或具名渲染属性组合内容。登记实际新增的共享组件及入口、调用场景和契约。
- 共享组件通过公开的 Props、回调及样式入口组合，依赖方向从业务页面指向共享组件。先复用或扩展现有组件和样式变量，复查全部受影响调用方。键盘操作、焦点、滚动容器及错误反馈在真实界面按改动验证。
- 加载、空态、失败和禁用态显式呈现，状态和操作带可读文本，颜色用于辅助区分。看板、任务详情、主对话请示可复用状态映射。设备连接与任务运行分别呈现，设备离线时保留最后确认的运行状态。
- 同一数据入口处理快照、SSE 订阅、重连游标和去重。组件从共享数据读取状态，通过输入更新。[项目组件规范](../../../../.wiki/02-开发指南/03-前端组件与复用.md)

## 验证范围和证据

从最接近变更的现有检查开始。全项目验证用 `pnpm check`，统一运行 Go 格式检查、静态分析与测试、ESLint、工作区 TypeScript 类型检查、工程工具测试、dsh 插件编译与测试，以及 Wiki 和 Skill 检查。单元测试验证状态、解析和失败分支，集成测试验证真实事务、连接和进程。涉及跨设备、原生 CLI 续接和 IM 时，按当前实现和授权验证实际链路，记录环境导致的缺口。

| 涉及范围 | 按风险选择验证 |
| --- | --- |
| Go Hub、运行器、本机命令 | 在仓库根目录执行针对包的 `go test`。跨包变更运行 `go test ./...`，编译入口变更时运行 `go build ./...`。 |
| Go 公开声明与包注释 | 按候选运行 `pnpm run lint:go-docs --base <基线> [--staged \| --ref <待推SHA>] [-- <路径>...]`，分别对应工作区、index 和提交内容。语义核对按代码注释规范执行。 |
| PostgreSQL 与迁移 | 将 `MUSTER_TEST_DATABASE_URL` 指向临时测试库，执行 `go test ./internal/hub/postgres ./internal/hub/httpapi`。核对历史回填、事务并发、幂等和重启后的状态。 |
| Windows Wails 设备 | 使用 `pnpm run check:go` 准备嵌入资源并以生产构建标签检查桌面模块。按影响运行 `wails3 task build`。窗口、托盘、实际配对和更新按对应用户操作实测。 |
| Web、插件、设备 UI | 执行 `pnpm run lint` 和受影响包的 `typecheck`，如 `pnpm --filter @agent-muster/web typecheck`。跨包构建使用 `pnpm run build`。插件变更按需构建后运行 `pnpm --filter muster-dsh test`。 |
| 工程检查工具及规则 | 运行 `pnpm run test:tooling`。涉及检查器语法、边界或自动修复行为时核对具体回归场景。 |
| 仅文档或 skill | Wiki 运行 `pnpm run docs:check`，核对索引、链接、锚点和元数据。Skill 核对入口、引用、元数据、命令及规则与实现事实。 |

触及运行闭环时，按影响验证以下场景。

- 确认丢失后用同一运行 ID 和事件序号重传，Hub 返回已有确认。旧轮次回执归所属轮次。
- Web 和 IM 对同一请示并发答复时只有一个有效答案和一次续接，离线保留答复并在上线后继续。
- daemon 在 CLI 活动或退出后重启，按本机记录核对进程归属，监控原进程或补报退出证据，同一原生会话最多一个写入轮次。
- SSE 在交错事务之后按已确认游标补读，游标过期时重新获取快照。
- 自动交付的测试与启用的独立 Review 对应同一候选 SHA，候选变化后重验，推送后读回远端引用。
- 损坏的 CLI 回执保留已产生的文件和原回复，恢复时补写回执。推送响应丢失时读远端引用判断结果。

记录命令或操作、退出结果、环境与版本、验证对应的 index tree 或提交 SHA、失败日志位置及未覆盖场景。说明失败源于本次变更、既有基线还是环境。产品验收按当前功能状态选择，不将仍处于设计阶段的链路列为已验证。[项目验证规范](../../../../.wiki/02-开发指南/01-验证与测试.md)

## 文档与目录

- `.wiki/` 收录长期知识。开发约定归开发指南，内部协议和维护指南归对应模块，稳定对外契约归对外方法，安装和最短运行路径归快速上手。每条事实维护一个权威来源，其他页面摘要并链接。
- `.docs/` 用于阶段设计、调研和迁移说明。实现落地后把需要长期维护的内容整理到 Wiki，阶段性文件按任务范围清理。设计结论注明阶段和待验证项，已实现信息引用对应源码、配置及测试。`.upstream/` 保存参考仓库，引用行为时记录上游提交。`.tmp/` 保存临时调试或验证材料。
- 新建或拆分 Wiki 页时使用项目模板，核对事实来源与各级索引可达性。目录深度、正文规模、附件和元数据执行现有文档约定。阶段性审查记录放在 `.tmp/`。[项目文档约定](../../../../.wiki/00-文档约定/INDEX.md)
